# WGSMapSet/3 構造仕様

## 第1章 概要

`WGSMapSet/3` は、複数の `WGSMap/3 + GI01` 由来の画像領域を1ファイルに束ねるためのコンテナ形式である。

`WGSMapSet/3` に格納できる画像データチャンクは `GI01` のみであり、`GI00` を含めてはならない。

`WGSMapSet/3` は以下のチャンク列で構成する。

```text
[WGSMapSetHeaderChunk: GLCH]
[LayoutChunk: LAYO]    任意。現在は省略する。
[GI01 chunk 0]
[GI01 chunk 1]
...
[GI01 chunk N-1]
```

各 `GI01` チャンクは、対応するマップ領域のラスタ本体を格納する。
各マップ領域の世界座標系上の原点は、`GLCH` 内のマップテーブルで定義する。

本仕様では、チャンクへの直接オフセットや空間インデックスは定義しない。
ただし、将来の拡張用として `GLCH` の直後に省略可能な `LayoutChunk` を配置できる。
現在の実装では `LayoutChunk` は出力しない。

## 第2章 チャンク共通構造

すべてのチャンクは以下の共通構造に従う。

| フィールド | 型 | 内容 |
| --- | --- | --- |
| チャンク名 | BYTE[4] | チャンク種別を示す識別子 |
| サイズ | MBUInt | チャンクデータ部のバイト長 |
| データ部 | BYTE[] | チャンクごとの固有データ |

`WGSMapSet/3` のヘッダチャンク名は `GLCH` である。
`LayoutChunk` のチャンク名は `LAYO` である。
後続の画像データチャンク名は `GI01` である。

## 第3章 WGSMapSetHeaderChunk

`WGSMapSetHeaderChunk` は、マップセット全体の座標解像度、メタデータ、格納するマップ数、各マップの原点を定義する。

チャンク名は `GLCH` である。

### 3.1 データ部構造

| フィールド | 型 | 内容 |
| --- | --- | --- |
| VERSION | BYTE[16] | 固定文字列 `WGSMapSet/3` |
| unit_inv_x | MBUInt | 経度方向の逆解像度 |
| unit_inv_y | MBUInt | 緯度方向の逆解像度 |
| metadata_len | MBUInt | メタデータ文字列のバイト長 |
| metadata | BYTE[] | UTF-8メタデータ。`metadata_len == 0` の場合は省略 |
| num_of_maps | MBUInt | 後続するマップ数 |
| map_table | MapEntry[] | 各マップの原点配列 |

`VERSION` は16バイトのBStrとして格納する。
文字列本体が16バイト未満の場合、残りは `0x00` で埋める。

### 3.2 MapEntry

`map_table` は `num_of_maps` 個の `MapEntry` を連続して格納する。

| フィールド | 型 | 内容 |
| --- | --- | --- |
| west | MBInt | 対応する `GI01` チャンクの左端経度インデックス |
| south | MBInt | 対応する `GI01` チャンクの下端緯度インデックス |

`MapEntry[i]` は、ヘッダ直後から数えて `i` 番目の `GI01` チャンクに対応する。

## 第4章 LayoutChunk

`LayoutChunk` は、将来の拡張として後続 `GI01` チャンクの配置情報を格納するための任意チャンクである。

チャンク名は `LAYO` である。

現在の仕様では、`LayoutChunk` のデータ部構造は未定義であり、通常は省略する。
Readerは、`GLCH` の直後に `LAYO` チャンクが存在する場合、既知の形式であれば解釈し、未対応であれば読み飛ばせる必要がある。

想定される将来用途は以下である。

- `GI01` チャンクごとのファイル内オフセット
- `GI01` チャンクごとのバイトサイズ
- 空間検索用の配置テーブル
- 読み出し高速化用の補助インデックス

`LayoutChunk` が省略された場合、Readerは `GLCH` 直後から `GI01` チャンク列が始まるものとして処理する。

## 第5章 後続GI01チャンク列

`WGSMapSetHeaderChunk` の直後には、`num_of_maps` 個の `GI01` チャンクを連続して格納する。
ただし、`LayoutChunk` が存在する場合は、その直後から `GI01` チャンク列を格納する。

```text
[GLCH]
[LAYO] optional
[GI01 for map_table[0]]
[GI01 for map_table[1]]
...
[GI01 for map_table[num_of_maps-1]]
```

`GI01` チャンクの内部構造は `wgsmap3仕様書.md` およびGI01各仕様に従う。

各 `GI01` チャンクは単体の `WGSMap/3` ヘッダを持たない。
世界座標系上の原点は、対応する `MapEntry` の `west`, `south` から得る。
解像度は `WGSMapSetHeaderChunk` の `unit_inv_x`, `unit_inv_y` を共有する。

## 第6章 座標系と領域

`MapEntry` の `west`, `south` は、対応する `GI01` チャンク内ラスタのローカル座標 `(0, 0)` に対応する世界座標インデックスである。

`GI01` チャンクの幅を `width`、高さを `height` とすると、そのマップ領域は次の範囲である。

```text
west  <= x < west  + width
south <= y < south + height
```

マップセット全体の領域は、全 `GI01` チャンク領域の外接矩形である。

## 第7章 読み出し規則

### 7.1 単一点読み出し

単一点 `(x, y)` を読み出す場合、各 `MapEntry` と対応 `GI01` チャンクの領域を順に確認する。

対象点がチャンク領域に含まれる場合、ローカル座標は次の通りである。

```text
local_x = x - west
local_y = y - south
```

複数のチャンク領域が重複する場合、先に格納されたチャンクを優先する。
ただし、値 `0` は未設定値として扱い、後続チャンクに非0値がある場合はその値を採用してよい。

### 7.2 矩形読み出し

矩形領域を読み出す場合、要求領域と各チャンク領域の交差範囲を求め、該当する `GI01` チャンクから値を復元して出力ラスタへ合成する。

合成時、値 `0` は既存値を上書きしない。

## 第8章 WGSMapSet/2 との差異

`WGSMapSet/2` は既存実装上、後続チャンクとして `GI00` を前提とする。

`WGSMapSet/3` は後続チャンクとして `GI01` のみを許可する。
`WGSMap/2`、`GI00`、または他の画像チャンクを混在させてはならない。

## 第9章 インデックスデータ

本仕様では、チャンクオフセットテーブルや空間インデックスの具体的なデータ構造は定義しない。

Readerは、ヘッダ直後から `GI01` チャンクを順に読み進めることで、`MapEntry` とチャンクを対応付ける。
将来、ランダムアクセス性能を改善する場合は、省略可能な `LayoutChunk` に後続 `GI01` チャンクの配置情報を格納する。
