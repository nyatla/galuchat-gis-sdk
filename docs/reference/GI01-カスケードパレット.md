# 1. 概要

カスケードパレットは、GI01のノードブロック内で共有されるパレット状態である。
ContainerNode、Raw/P、RLE/Pは、値そのものを毎回出力せず、カスケードパレット上のインデックスを参照して値を復元する。

パレット状態はノード単位で独立しておらず、シリアライズ順に従って後続ノードへ引き継がれる。
あるノードで行われたパレット更新は、そのノードの子孫だけでなく、後続にシリアライズされる兄弟ノードや別階層のノードにも影響する。

GI01のカスケードパレットは最大16スロットを持つ。
使用するノード種別によって、参照・更新に使うスロット範囲と、更新制御の記録位置が異なる。

---

# 2. 更新タイミングと伝播の仕方

## 2.1 更新タイミング

カスケードパレットは、パレット参照形式のノードをシリアライズまたはデシリアライズするときに更新される。

更新値列が出現する場合、その値列はノード種別ごとの更新制御に従ってカスケードパレットを上書きする。
更新値列が出現しない場合、カスケードパレットは変更されず、現在の状態をそのまま参照する。

更新数はノード種別ごとに異なる制御情報で表される。

| ノード種別 | 更新制御 | 更新対象 |
|------------|----------|----------|
| ContainerNode | CellHeader下位4bitの`UpdatePalletTable4` | Slot0～3 |
| Raw/P Palette Resolution=`00` | CellHeader下位2bitの`UpdatePalletTable2` | Slot0～1 |
| Raw/P Palette Resolution=`01` | CellHeader下位4bitの`UpdatePalletTable4` | Slot0～3 |
| Raw/P Palette Resolution=`10` | CellHeader下位4bitと後続12bitの`UpdatePalletTable16` | Slot0～15 |
| Raw/N Palette Resolution=`11` | なし | カスケードパレット不使用 |
| RLE/P Palette Resolution=`00` | PalletHeader bit5-4の`UpdatePalletTable2` | Slot0～1 |
| RLE/P Palette Resolution=`01` | PalletHeader bit6-4の`UpdatePalletTable3` | Slot0～2 |
| RLE/P Palette Resolution=`10` | PalletHeader bit8-4の`UpdatePalletTable5` | Slot0～4 |
| RLE/P Palette Resolution=`11` | PalletHeader bit19-4の`UpdatePalletTable16` | Slot0～15 |

## 2.2 伝播の仕方

カスケードパレットは、ノードブロックを走査してシリアライズする順序に従って伝播する。
親子関係によるローカルスコープではなく、同一ノードブロック内の共有状態として扱う。

例：

```
初期状態: [10, 20, 30, 40, ...]

ノードA: パレット更新 [15, 25]
更新後: [15, 25, 30, 40, ...]

ノードB: パレット更新なし
参照値: [15, 25, 30, 40, ...]

ノードC: パレット更新 [7, 8, 9, 11]
更新後: [7, 8, 9, 11, ...]
```

復号側は、ノードを読み出すたびに同じカスケードパレット状態を更新しながら処理する必要がある。
任意のノードだけを切り出して復元する場合は、そのノードに到達する直前のカスケードパレット状態が必要になる。


## 2.3 `UpdatePalletTable`

カスケードパレットはそのノードが参照する範囲のみが有効値となる。すなわち、ノードのパレットが２色の場合、そのノードでは、先頭から２つのパレットだけが有効である。

エンコーダは、各ノードのパレット値列を昇順に正規化して記録する。

この時、符号化モードごとの固定幅のビット配列である`UpdatePalletTable`を更新位置フラグとして利用し、さらにそのビット配列中の1ビットの個数を更新パレット数とすることで、同値パレットの更新を抑制することができる。

* ビット配列は、上位から、Slot0,Slot1,...Slotnとする。
* 例えば、1010の場合は、4スロット、0,2スロット更新有、更新数２となり、パレット値は、Slot0,Slot2の値の順で置く。

### コンテナノードへの適応
コンテナノードは、最大4値のパレットを更新する可能性があるので、3-0に4ビットのフィールド`UpdatePalletTable4`を割り当てることで、後続のパレット数と更新位置を制御する。
（旧NumOfPalletは廃止する）

### RLE Palette Resolution=00(1/2値)への適応
RLEノードPalette Resolution=00には、PalletHeaderの5-4に2ビットのフィールド`UpdatePalletTable2`を割り当てることで、後続のパレット数と更新位置を制御する。

* 1値の場合は、末尾のビットは常に0となる。
* 2値の場合のみ、末尾ビットに1の可能性がある。

### RLE Palette Resolution=01(3値)への適応
RLEノードPalette Resolution=01には、9bit PalletHeaderの6-4に3ビットのフィールド`UpdatePalletTable3`を割り当てることで、後続のパレット数と更新位置を制御する。

### RLE Palette Resolution=10(4-5値)への適応
RLEノードPalette Resolution=10には、12bit PalletHeaderの8-4に5ビットのフィールド`UpdatePalletTable5`を割り当てることで、後続のパレット数と更新位置を制御する。

* 4値の場合は、末尾のビットは常に0となる。
* 5値の場合のみ、末尾ビットに1の可能性がある。

### RLE Palette Resolution=11(6-16値)への適応
RLEノードPalette Resolution=11には、20bit PalletHeaderの19-4に16ビットのフィールド`UpdatePalletTable16`を割り当てることで、後続のパレット数と更新位置を制御する。
`UpdatePalletTable16`は上位bitからSlot0、Slot1、...、Slot15に対応する。

### Raw/P（パレット使用）への適応
Palette Resolutionが`00`の場合は、CellHeader下位2bitを`UpdatePalletTable2`として使用する。CellHeader bit3-2は予約0である。

Palette Resolutionが`01`の場合は、CellHeader下位4bitを`UpdatePalletTable4`として使用する。

Palette Resolutionが`10`の場合は、CellHeader下位4bitを`UpdatePalletTable16`の下位4bitとして使用し、CellHeader直後の12bitを上位12bitとして記録する。

Palette Resolutionが`11`の場合はRaw/Nであり、値列を直接記録するためカスケードパレットを使用しない。CellHeader下位4bitは予約0である。

## 2.4 更新値列の扱い

更新値列は、`UpdatePalletTable`を持つノードについては、対象スロットを特定し、その部分について上書きする。
Raw/PとRLE/Pはすべて`UpdatePalletTable`を持つ。


例えば、`UpdatePalletTable4=1010`、更新値列が`[1, 5]`の場合、Slot0とSlot2だけを更新する。

```
更新前: [10, 20, 30, 40, ...]
更新フラグ: 1010
更新値: [1, 5]
更新後: [1, 20, 5, 40, ...]
```

Raw/P Palette Resolution=`10`で、パレット更新数が`3`、更新値列が`[1, 3, 5]`の場合、更新後の先頭3スロットは以下になる。

```
更新前: [10, 20, 30, 40, ...]
更新値: [1, 3, 5]
更新後: [1, 3, 5, 40, ...]
```

更新フラグまたは更新数が`0`の場合、スロットは一切変更されない。


# 3. カスケードパレットを使用するノード

## 3.1 ContainerNode

ContainerNodeは、値を表す子要素をカスケードパレットのインデックスとして保持する。

CellHeaderの`UpdatePalletTable4`が更新対象スロットを示し、更新値列は指定されたスロットに反映される。
ContainerNodeはIndex 0～3を参照し、最大4スロットまで更新できる。

ContainerTypeごとの参照方法は次の通りである。

| ContainerType | 用途 | 参照方法 |
|---------------|------|----------|
| `00` | 混載 | PalletMaskの`00`～`10`がIndex 0～2、`11`が子ノード |
| `01` | 値のみ | PalletMaskの`00`～`11`がIndex 0～3 |
| `10` | 単一値 | PalletMaskなし。Index 0を参照 |

## 3.2 Raw/P

Raw/Pは、画素値をカスケードパレットのインデックス列として記録する形式である。

CellHeaderのPalette Resolutionが`00`～`10`の場合、Raw/Pとして扱う。
パレット値列が出現する場合は、Palette Resolutionごとの更新制御に従ってカスケードパレットを更新し、その後のインデックス列が更新後のパレットを参照する。

Palette Resolutionが`11`のRaw/N形式では、値列を直接記録するためカスケードパレットは使用しない。

## 3.3 RLE/P

RLE/Pは、ランの値をカスケードパレットのインデックスとして記録する形式である。

CellHeaderのPalette Resolutionが`00`～`11`の場合、RLE/Pとして扱う。
すべてのPalette Resolutionで、PalletHeaderの`UpdatePalletTable`により更新対象スロットを指定する。
更新対象がない場合は、既存のカスケードパレットをそのまま参照する。

Palette Resolutionごとの参照方法は次の通りである。

| Palette Resolution | 対象パレット数 | インデックス表現 |
|--------------------|----------------|------------------|
| `00` | 1～2値 | 初期インデックスと交互展開 |
| `01` | 3値 | 初期インデックスと1bit差分 |
| `10` | 4～5値 | 初期インデックスと2bit差分 |
| `11` | 6～16値 | 4bit即値インデックス |

# 4.記録値の差分化

カスケードパレットは、各ルートノードでの初期値を0として扱う。
更新値列の記録形式は、ブロックヘッダのパレット格納形式に従う。

パレット格納形式がMBUIntの場合、更新値列は絶対値として記録する。
パレット格納形式がMBINT-Dの場合、更新値列は更新前のそのスロットの値との差分値をMBIntで記録する。

この方式は、元データの値分布が近隣で近い傾向にある場合に記録値幅の削減に寄与する。
