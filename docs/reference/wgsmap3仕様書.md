# wgsmap3仕様書

## 第1章 ファイル構造全体

WGSMapフォーマットは、以下の2つの主要チャンクから構成される：

1. `WGSMapHeaderChunk`（チャンク識別子: "GLCH"）
2. `GaluchatImageDataChunk`（チャンク識別子: "GI01"）

各チャンクは共通の構造（チャンク名 + サイズ + データ部）を持ち、連続したバイナリ構造として`.wgsmap.glc`ファイルに格納される。
WGSMap/3に搭載できる画像データチャンクはGI01のみであり、GI00を含むことはできない。

### 1.1 チャンク共通構造

すべてのチャンクは以下の共通構造に従って構成される：

| フィールド | 型      | 内容                              |
| ----- | ------ | ------------------------------- |
| チャンク名 | 4バイト   | チャンク種別を示す識別子（例: "GLCH", "GI01"） |
| サイズ   | MBUInt | チャンクのデータ部（payload）のバイト長         |
| データ部  | バイト列   | チャンクごとに定義される固有構造体               |

```
+------------------------+
| チャンク: GLCH        |
+------------------------+
| チャンク: GI01        |
+------------------------+
```

## 第2章 WGSMapHeaderChunk 構造

このチャンクは、WGSMap全体の空間解像度・座標基準・メタ情報を定義するメタデータチャンクであり、チャンク名は "GLCH"。

### 2.1 チャンク内部構造

| フィールド         | 型         | 内容                          |
| ------------- | --------- | --------------------------- |
| VERSION       | BYTE\[16] | 固定文字列 "WGSMap/3"（バージョン識別子）  |
| unit\_inv\_x  | MBUInt    | 経度方向の逆解像度（ピクセル／度）           |
| unit\_inv\_y  | MBUInt    | 緯度方向の逆解像度（ピクセル／度）           |
| west          | MBInt     | 左上ピクセル (0,0) に対応する経度インデックス  |
| south         | MBInt     | 左上ピクセル (0,0) に対応する緯度インデックス  |
| metadata\_len | MBUInt    | メタデータ文字列の長さ（省略可）            |
| metadata      | BYTE\[]   | UTF-8形式のメタ情報文字列（長さが0であれば省略） |

## 第3章 GaluchatImageDataChunk 構造

このチャンクは、画像本体を square\_unit × square\_unit のブロック単位に分割し、Galuchatブロックフォーマットで圧縮・格納する。 チャンク名は "GI01" である。

### 3.1 チャンク構造

| フィールド        | 型      | 内容                       |
| ------------ | ------ | ------------------------ |
| チャンク名        | 4バイト   | 固定値 "GI01"               |
| サイズ          | MBUInt | データ部（以下全体）のバイト長          |
| width        | MBUInt | 入力画像の幅（ピクセル）             |
| height       | MBUInt | 入力画像の高さ（ピクセル）            |
| square\_unit\_log2 | UINT8  | ブロックサイズを`2^n`で表す指数値 |
| ブロック配列       | バイト列   | 各ブロック（画像左上からrow-major順）  |

### 3.2 ブロック構造

各ブロックは以下の順で構成される：

| フィールド        | 型       | 内容                                       |
| ------------ | ------- | ---------------------------------------- |
| BlockHeader  | UINT8   | ブロック格納方式などのヘッダ |
| BlockSize    | MBUInt? | 圧縮形式によっては存在（CC\_RAWは省略）                  |
| BlockPayload | バイト列    | GI01ノード構造（ContainerNode または BaseDataNode） |

※補足：BlockSize フィールドは、圧縮形式によって有無が決まる可変フィールドです。

* `CC_RAW` ではサイズ情報が不要なため、このフィールドは格納されません。BlockPayloadの終端はノード構造の自己完結性により判断される。
* `CC_RAWS` および `CC_LZSS` では、後続の BlockPayload のバイト長を指定するために必ず付与されます。

このように圧縮形式ごとに条件付きで出現するため、「BlockSize は形式により存在する（optional）」という意味で `MBUInt?` という注記表記を行っています。

### 3.3 BlockHeader
ブロック内のパレット更新値記録方式とBlockPayload圧縮形式を指定する。

| Bit | 名称       | 内容                           |
| - | -------- | ---------------------------- |
| 7 | パレット格納形式 | カスケードパレット値の格納方式 |
| 6 | 予約 | 0 |
| 5-4 | 圧縮形式 | BlockPayloadの圧縮形式 |
| 3-0 | 予約 | 0|

#### パレット格納形式
カスケードパレットのスロット更新値の記録形式を指定する。
| 値 | 名称       | 内容                           |
| - | -------- | ---------------------------- |
| 0 | MBUInt  | カスケードパレット値をMBUIntで格納する |
| 1 | MBINT-D | カスケードパレット値を、更新前の値との差分値としてMBIntで格納する |


#### 圧縮形式
BlockPayloadの圧縮形式を示す。

| 値 | 名称       | 内容                           |
| - | -------- | ---------------------------- |
| 0 | CC\_RAW  | 非圧縮・サイズ指定なし（構造により終端判定）       |
| 1 | CC\_RAWS | 非圧縮・サイズ指定あり（BlockSizeが必要）    |
| 2 | CC\_LZSS | LZSS圧縮・サイズ指定あり（BlockSizeが必要） |



圧縮形式の値`3`は予約であり、使用してはならない。

### 3.4 ブロック走査順

ブロック配列は画像左上から右方向、右端到達後に1行下に移動するラスタースキャン順（row-major order）で格納される：

```
   x→
 y +---+---+---+
 ↓ | 0 | 1 | 2 |
   +---+---+---+
   | 3 | 4 | 5 |
   +---+---+---+
```

### 3.5 チャンク本体の構造

GI01チャンクのデータ部は、`width`、`height`、`square_unit_log2`に続いて、ブロック配列を直列に格納する。
各ブロックの位置はブロック配列内の順序から決定する。

```
[width: MBUInt]
[height: MBUInt]
[square_unit_log2: UINT8]
[Block 0]
[Block 1]
...
[Block N-1]
```

ブロック数は次の式で決定する。

```
horizontal_units = ceil(width / square_unit)
vertical_units   = ceil(height / square_unit)
block_count      = horizontal_units * vertical_units
```

ここで`square_unit = 2 ^ square_unit_log2`である。

### 3.6 格納されるノード型

各ブロックのBlockPayloadには、GI01ノードツリーを1個格納する。
ルートノードは`ContainerNode`または`BaseDataNode`であり、`BaseDataNode`の具象形式として`RawNode`、`RawPalletNode`、`RlePalletNode`系ノードを使用する。
ノード構造の詳細は、GI01のContainerNode、Raw DataNode、RLE DataNode仕様に従う。
